## 2026-07

- 2026-07-12 [tv][stripe][claude] +1 day TV bot access buffer + failure diagnostics (PR #33). Bot infra reads the offset-less UTC expiry timestamp as MSK and revoked access ~3h before Stripe's auto-charge; every grant/rename payload now pads expiry by `BOT_EXPIRY_BUFFER_DAYS` (1, skipped for lifetime) via the `ActivateTradingViewAccessDto.grant()` / `ChangeTradingViewNameDto.rename()` factories — the padded value is what gets persisted to the retry queue, so retries never compound it. Bot failures now log the real HTTP status + response body (previously discarded) and store it in the retry job's `lastError`. Two parts of the original PR were dropped in pre-merge review and did NOT ship: the whole-second `@JsonFormat` pin on the bot DTOs (its deserializer side would have DEAD-ended legacy fractional-second retry-queue payloads) and the `@Retry` switch to `client-error-included` (a no-op — that config had no `resilience4j.retry.instances` binding). (`ea8ec83`)
